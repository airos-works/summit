# HTML5test, 18 November 2026

[html5test.co](https://html5test.co/) scores how many web-platform features a
browser exposes (588 points). It checks that features are present, not that
they work. The same page was run in Summit, the current Chrome and the current
Firefox on the same day. The [machine-readable report](html5test-2026-11-18.json)
lists each browser's build, user agent and every row the page marked missing.

| Browser | Score |
| --- | ---: |
| Chrome 158.0.8127.36 (Chrome for Testing, current stable) | 572 / 588 |
| **Summit 0.1.0~git20261116.1923** | **565 / 588** |
| Firefox 160.0.1 | 547 / 588 |

The page's own "Other browsers" tables stop in 2018 (Chrome 66, 528 points)
and were not used.

## What Summit misses

Summit misses 23 points: six features, and one point because speech
recognition is exposed only with WebKit's prefix (`webkitSpeechRecognition`,
which scores 1 of 2).

| Feature | Points | Why |
| --- | ---: | --- |
| Device Orientation | 3 | Not built for Haiku; no orientation sensors |
| Device Motion | 2 | As above |
| Generic Sensor API | 5 | Not in WebKit (Chrome only) |
| Web Payments (Payment Request) | 5 | WebKit's Payment Request supports only Apple Pay, so other ports leave it off |
| WebXR | 5 | Not built for Haiku; no XR devices |
| Speech Synthesis | 2 | The engine has `speechSynthesis` ([web-apis.md](web-apis.md#speech-synthesis-145)), but the page also wants voices, and air/OS images ship no eSpeak yet (airos-works/haiku#52) |
| Speech Recognition, unprefixed | 1 | Only `webkitSpeechRecognition` ([speech-recognition.md](speech-recognition.md)) |

The other rows marked missing carry no points: optional codecs (AAC in a
plain `<audio>`, H.265 and Dolby audio in streams), JPEG XR and HEIC canvas
encoding, the 2D `OffscreenCanvas` check
([web-platform-issues.md](web-platform-issues.md) explains why that probe
fails), Web NFC, and features the page lists as rejected or dropped
(WebVR, Application Cache, Web SQL, the FileSystem API).

For comparison, Chrome loses its points to Web Bluetooth (5, headless),
audio/video track selection (4), the HTML5 tokenizer check (3), speech
synthesis (2, no voices headless), `accessKeyLabel` and canvas hit testing.
Firefox loses them to `<input type=month>` and `week` (8), the Generic Sensor
API, Web Bluetooth, WebUSB, Payment Request and WebXR (5 each), track
selection (4), speech synthesis (2), the `ping` attribute and canvas hit
testing.

## How it was run

- **Summit:** the air/OS x86_64 image `20261117-0606-hrev60207-2758-g7499ff568c`
  with its bundled Summit (`summit` and `summit_webkit` 1.10.1~git20261116.1923),
  live in a QEMU/KVM VM (8 CPUs, 8 GiB, standard VGA, so no GPU acceleration)
  made with `tools/haiku-vm/make-stock-vm.sh`. Summit ran in a normal window
  with a fresh profile and read its result through its MCP server
  (`evaluate`). No row the page scores depends on a GPU.
- **Chrome and Firefox:** on the Ubuntu 26.04 build host, headless, driven by
  ChromeDriver 158.0.8127.36 and geckodriver 0.37.1. Firefox was given FFmpeg
  (libavcodec 62) so it can play H.264; the codec rows carry no points, and its
  score was 547 with and without it.
- Every browser's result was read from the finished page: the score and each
  table row with the `missing` class. html5test.co serves the test of
  [niutech/html5test](https://github.com/niutech/html5test) commit `4b6f655`
  (`scripts/9/data.js` is identical).

A headless browser can report less than a windowed one (Chrome's Web
Bluetooth and speech voices), so Chrome's and Firefox's scores here are a
lower bound for those browsers on a desktop.
